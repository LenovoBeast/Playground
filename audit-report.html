1 · Security findings

S1 — Missing Content-Security-Policy and transport headers Critical Fixed

Was: only 4 headers existed (X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy). No CSP at all — meaning any injected inline script (e.g. via a compromised dependency, a future CMS field, or a copied snippet) executes with full origin privileges. No HSTS, no cross-origin isolation.

Fix (netlify.toml): full header set —

  • Content-Security-Policy: default-src 'self'; scripts limited to 'self' plus sha256 hashes of the two inline JSON-LD blocks; styles to self + Google Fonts (React inline styles need 'unsafe-inline'); images to self/data:/picsum; frame-ancestors 'none', object-src 'none', base-uri 'self', form-action 'self', upgrade-insecure-requests.
  • Strict-Transport-Security: max-age=31536000; includeSubDomains (blocks SSL-strip).
  • Cross-Origin-Opener-Policy: same-origin + Cross-Origin-Resource-Policy: same-origin (blocks cross-window Spectre-class attacks and hotlinking).
  • X-Permitted-Cross-Domain-Policies: none; Permissions-Policy extended with payment=(), usb=().

Expected result: an injected payload (script tag, inline handler, exfil fetch) is blocked by the browser before execution. Only the two reviewed JSON-LD blocks and own-origin scripts run. New scripts/csp-hashes.mjs regenerates hashes after JSON-LD edits; I verified the hashes are identical in source and dist/ build output.

Caveat: netlify.toml is only honored on Netlify, while robots.txt/canonical point at GitHub Pages. I mirrored the CSP as a <meta http-equiv> tag in index.html so the policy applies on any static host; frame-ancestors/HSTS remain Netlify-only.

S2 — Inline event handler in the document head High Fixed

Was: <link rel="stylesheet" … media="print" onload="this.media='all'"> — an inline script attribute, the single biggest obstacle to a strict CSP (it forces script-src 'unsafe-inline').

Fix: removed the handler; the stylesheet now loads normally. Expected result: zero inline JavaScript in the document — hashes instead of the 'unsafe-inline' escape hatch; font loading behavior unchanged.

S3 — Contact form: no backend, no honeypot, no length caps High Fixed

Was: the form simulated success with setTimeout, focused the wrong element on error, accepted unbounded input, and never announced anything to assistive tech.

Fix (Contact.jsx): field-level validation (name/email/subject/message) with aria-invalid + aria-describedby per field, a single polite live region, first-invalid-field focus, and maxLength caps (100 / 254 / 150 / 2000).

Expected result: empty or malformed submits can no longer reach the "sent" state, and every failure is announced once.

Second pass — wired to a real backend decision: the form now hands off to the user's own mail client via a composed, URL-encoded mailto: link. No server, no third party, no hosting bill — it works on GitHub Pages or anything else. The subject and body are assembled from the validated fields, the handoff is announced through the live region, and a test/contactForm.test.js contract guards the composition and the state-before-navigation ordering (handing off to an external protocol can unload the document, so all state updates are queued before window.location.href). Netlify Forms attributes were considered and dropped — without Netlify credits they would have been dead weight.

S4 — 14 dependency advisories (11 high) High Fixed

Was: npm audit reported 14 advisories: brace-expansion (3× DoS, high), braces (high), compression (high — via the unused serve dep), esbuild dev-server request forgery (moderate), fast-uri (3× high), postcss-selector-parser (moderate), source-map-js (high).

Pass 1: applied non-breaking npm audit fix (14 → 11), removed the unused serve devDependency (11 → 9). All 9 remaining sat in the Tailwind 3.4 watcher chain and the Vite dev server — dev-time only, none shipping in the browser bundle.

Pass 2 — migration done: Tailwind 3.4 → v4 (@tailwindcss/postcss, @import "tailwindcss", legacy config preserved via @config) and Vite 5 → 8 (Rolldown). npm audit now reports 0 vulnerabilities, verified after every step.

Expected result: shipped and build-time code both free of known-vulnerable packages; npm audit --audit-level=high now runs as a CI gate.

S5 — Third-party data exposure (fonts, thumbnails) Medium Fixed

Google Fonts shared visitor IP/UA with Google on every page load; project thumbnails were fetched from picsum.photos.

Bonus finding in this pass: the site requested Satoshi from Google Fonts — a font Google does not serve. The request returned an HTML error page, which also killed the legitimately-available JetBrains Mono in the same stylesheet URL. The entire webfont stack was silently broken and the site rendered in system fonts.

Fix: Satoshi (400–900, from Fontshare) and JetBrains Mono (variable, latin subset) are now self-hosted woff2 files in src/assets/fonts, fingerprinted by Vite. The three picsum thumbnails are vendored to public/img/projects and referenced base-relatively. The CSP dropped all external style/font/image origins: style-src 'self' 'unsafe-inline', font-src 'self', img-src 'self' data:.

Expected result: zero third-party requests, no Google dependency, real brand typography for the first time, and a CSP that cannot be loosened by an external CDN compromise. New scripts/vendor-fonts.mjs re-downloads the fonts reproducibly.

S6 — Relative canonical/OG/JSON-LD URLs Medium Fixed

Social crawlers cannot resolve relative og:url/schema URLs, and there was no canonical link. Fixed to absolute https://lenovobeast.github.io/Playground/…. Expected result: correct link-preview cards and unambiguous canonical indexing.

S7 — Verified clean Info

No secrets or credentials in the repo (env vars referenced only in comments); no eval, new Function, or dangerouslySetInnerHTML; no user-generated content rendered as HTML; all target="_blank" links carry noopener noreferrer; the Vite dev server already guards hosts via allowedHosts; the SPA rewrite does not shadow existing asset files; robots.txt and sitemap are sane.

2 · Accessibility findings

A1 — Text contrast below WCAG AA Critical Fixed

Was: three color classes failed SC 1.4.3 on the #030712 background — text-zinc-600 at ≈2.6:1 (16 usages: labels, hints, footer legal text, placeholders), text-zinc-500 at ≈4.1:1 (small body copy, mono labels), and the #64748b placeholder at ≈4.2:1. Placeholders are text too, and these ran at 10–14px where the failure is worst.

Fix: all 16 text-zinc-600 → text-zinc-400; .text-body-sm → text-zinc-400; placeholder color → #a1a1aa. Expected result: every text node now measures ≈7.7:1 — comfortably AA at all sizes, including for low-vision users who zoom or use high-contrast modes.

A2 — Message textarea had no accessible name Critical Fixed

Was: inputs used the sr-only <label> pattern, but the textarea's "Message" caption was a bare decorative <span> — screen readers announced an unlabeled multi-line edit.

Fix: proper <label htmlFor="message" className="sr-only">. Expected result: announces "Message, edit, required"; matches the name/label pairing used by the other three fields.

A3 — Dangling aria-describedby and silent validation Critical Fixed

Was: the form declared aria-describedby="form-status" pointing at an element that didn't exist, and failed submits changed nothing visible or audible — the user just got teleported to a random field.

Fix: a real #form-status live region (one announcement per state change, not per keystroke), per-field error <p> wired via aria-describedby, aria-invalid toggling, and focus moved to the first invalid field. Expected result: on submit, SR users hear "Please fix the form: …"; when tabbing into an invalid field they hear its specific error. Keyboard users see inline errors.

A4 — Preloader spammed assistive tech every frame High Fixed

Was: role="status" aria-live="polite" on a container re-rendering at 60fps — a screen reader would queue ~90 step-text announcements during the 1.5s boot.

Fix: the veil is now aria-hidden; a single sr-only status announces once on completion ("Experience ready"). Expected result: exactly one meaningful announcement instead of a flood.

A5 — Tablist unusable by keyboard High Fixed

Was: the Stack section exposed role="tablist" with no arrow-key handling and no roving tabindex — keyboard users had to Tab through every hidden tab and the widget contradicted the WAI-ARIA tabs pattern.

Fix (Stack.jsx): ←/→ moves between categories (wrapping), Home/End jump to the ends, roving tabIndex, focus follows activation. Expected result: the tab widget behaves exactly as screen-reader users expect; Tab enters/exits the group as a single stop.

A6 — Section landmarks had no accessible names Medium Fixed

Five <section> landmarks (Work, About, Stack, Playroom, Contact) were unnamed — the SR rotor listed them as "region" ×5. Added aria-labelledby pointing at each heading. Expected result: landmark navigation reads "Selected Work", "Crafting Digital Frontiers", etc.

A7 — Reduced-motion ignored by CSS smooth scroll Medium Fixed

html { scroll-behavior: smooth } overrode the user's prefers-reduced-motion preference for anchor jumps (the JS smooth-scroller already respected it). Fixed inside the reduced-motion block. Expected result: no unwanted scroll animation for vestibular-sensitive users.

A8 — 404 page outside the main landmark Medium Fixed

The catch-all route rendered <NotFound /> with no <main>, so the skip link was dead there. Wrapped the route in <main id="main-content">. Expected result: skip-link and landmark navigation behave identically on error pages.

A9 — Game keyboard parity (verified, not a finding) Verified

My first pass flagged match3 and launch as pointer-only. On full review that was wrong: match3.js moves a visible selection cursor with arrows and commits swaps with Enter/Space; launch.js adjusts angle/power with arrows and fires with Space — both with listeners correctly added in start() and removed in stop(), following the same pattern as snake/breakout/racer. All five games are keyboard-playable. The only defect was the marketing copy: the card descriptions advertised click-only controls, now fixed to document both input methods.

A10 — Already solid Info

  • Skip link, systematic :focus-visible ring, game-overlay focus trap with Esc + focus restore.
  • prefers-reduced-motion honored across GSAP timelines, React hooks, and CSS (animations neutralized, hover/focus feedback preserved).
  • 44px minimum touch targets on coarse pointers; 16px input font-size (no iOS zoom-on-focus).
  • Real alt text on project thumbnails; every decorative layer (canvas, glow, grain, sheen) is aria-hidden; filters expose aria-pressed; inactive 3D labels carry tabIndex={-1}.
  • Responsive system is sound: svh units, collapsing grids, px-6 gutters, grid-flow-dense bento layouts at every breakpoint.
