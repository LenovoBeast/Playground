1 · Findings

Severity reflects user-visible impact × likelihood. Every item was verified against the source, not inferred.

Architecture

A-1 — three.js loads eagerly on every route High

Root cause
World.jsx statically imports three/backdrop.js, which imports three. App renders <World> unconditionally, so the 514 kB vendor-three chunk (128 kB gzip) is in the entry graph and must be fetched, parsed, and evaluated before the hero paints.
Impact
Better first paint on every page for every visitor; mid-range phones feel it most. The 3D backdrop is decorative — it should never block content.

A-2 — No error boundary anywhere High

Root cause
Zero componentDidCatch/boundary classes. The app leans on several APIs that throw at runtime — WebGL context creation, GSAP timelines targeting refs, ResizeObserver — and any render-time error unmounts the whole tree.
Impact
One bad frame, one failed WebGL context on an old device, one ref-timing bug → white screen, no recovery, no message. For a portfolio whose job is to demonstrate competence, a white screen is the worst possible failure mode.

A-3 — Contact email is an undeliverable placeholder High

Root cause
lenovobeast@example.com — an RFC 2606 reserved domain that cannot receive mail — is hardcoded in Contact.jsx (form handoff target), Footer.jsx, and src/data/nav.js (socials).
Impact
The entire contact channel is dead. Every mailto click opens a composer addressed to a mailbox that does not exist. This is the site's conversion path.

A-4 — Preloader gates the app on a fixed timer High

Root cause
Preloader runs duration = 1500 ms plus a 700 ms outro — a hard floor of ~2.2 s before the hero is visible, regardless of whether the app was ready in 300 ms.
Impact
Every visitor pays a fixed tax on every visit. It also blocks the skip link and keyboard access to the page underneath (the veil has no inert/pointer-events management).

A-5 — Three bespoke 3D/game engines maintained in parallel Medium

Root cause
three/backdrop.js (constellation), world.js (playroom desk scene), and five separate games/*.js engines each implement their own render loop, resize handling, input wiring, and dispose. Organic growth — the site is a playground, so each demo got its own engine.
Impact
~3× the WebGL surface to audit; inconsistent dispose semantics (one leak pattern is a bug multiplied by six). This is partly by design — see constraints below — so the fix is consolidation, not removal.

A-6 — Hero defines components inside its render body Medium

Root cause
StatCard, TerminalWindow3D, and CodeLine are consts defined inside Hero(). Every Hero render creates new component identities, so React unmounts and remounts those subtrees instead of reconciling them.
Impact
Wasted DOM churn, lost internal state, memoization defeated, and GSAP timelines targeting those refs get rebound against remounted nodes. Tests must keep the exact tokens const TerminalWindow3D and <TerminalWindow3D /> when hoisting.

Performance

P-1 — ScrollTrigger positions go stale after layout changes Medium

Root cause
Zero ScrollTrigger.refresh() calls exist in the codebase. ProjectGrid changes page height on every filter change (AnimatePresence popLayout), Stack swaps tab panels, and lazy images shift layout — all without telling GSAP.
Impact
Animations and scroll-spy fire at wrong scroll positions; content appears to animate late or early; jank as triggers recalculate lazily mid-scroll. GSAP's own React integration guide calls this the #1 integration bug.

P-2 — Four independent scroll/rAF pipelines Low

Root cause
Nav's measure(), useActiveSection's measure(), World's per-frame setScroll, and App's CursorGlow each attach their own scroll listener + rAF loop. Two of them duplicate the same scrollY math.
Impact
Four rAF chains per scroll frame on a page that is otherwise GPU-heavy. Each is individually correct; together they compete for the main thread.

P-3 — Asset weight that doesn't need to exist Low

Root cause
Satoshi ships as four full-charset woff2 files (~101 kB total) for an English-only page; thumbnails are 192 kB of JPEG.
Impact
~180 kB of avoidable transfer. Latin subsetting typically cuts these woff2 files by 55–65 %; WebP/AVIF cuts the images by 60–75 %.

Maintainability

M-1 — CSS rot: duplicated rules and specificity fights Medium

Root cause
tailwind.css is 830+ hand-written lines accumulated across redesigns. .magnetic-btn is defined twice, :focus-visible exists globally and again as .focus-ring, and base element styles (input { width:100% }) silently fight the Tailwind utilities that components layer on top.
Impact
The next person to edit an input or button class can lose to a base rule they can't see. Duplicated blocks drift.

M-2 — The site advertises tooling it doesn't have Medium

Root cause
Stack.jsx lists "TypeScript — strict mode" as a core skill and ESLint/Prettier as project tooling. package.json contains none of them; the codebase is plain JSX with no lint config.
Impact
Credibility risk — a recruiter who clones the repo finds the claims are decorative. Also why drift like A-6 and M-1 goes unnoticed: there is no linter to catch dead or duplicated code.

M-3 — Tests only assert on source text Medium

Root cause
The node:test suite reads component files and regex-matches strings. That works for data invariants, but it's brittle to formatting and blind to runtime behavior — which is exactly why the smoke and a11y gates had to be bolted on separately.
Impact
A typo inside a JSX string passes; a genuinely broken render passes. Coverage over behavior is near zero.

Usability

U-1 — Mobile drawer has no focus trap Medium

Root cause
Nav's drawer handles Escape and aria-expanded/aria-controls, but focus can Tab straight out of the open drawer into the page behind it, and focus is not restored to the toggle on close. The game overlay implements the complete pattern — Nav just never got it.
Impact
Keyboard and screen-reader users can get lost behind an open overlay. WCAG 2.4.3 / 2.4.7 territory.

U-2 — CursorGlow ignores prefers-reduced-motion Low

Root cause
CursorGlow bails only on (hover: none). Its rAF loop runs a continuous lerp animation for users who explicitly asked for reduced motion — while every other animated layer correctly consults useReducedMotion.
Impact
A small, specific a11y inconsistency that the axe gate can't catch (it needs motion, not contrast).

U-3 — Soft 404s return HTTP 200 Low

Root cause
Unknown paths are client-routed to the NotFound component; GitHub Pages serves the shell with 200.
Impact
Crawlers can index soft-404s. Inherent to SPAs on GitHub Pages without edge rules — accepted with a note.

Verified good — keep these

  • Data integrity: projects.json single source of truth, true re-export, contract-tested.
  • Security posture: hash-pinned dual CSP, zero external origins, 0 audit findings, CI gate.
  • Bundle shape: vendor split; main chunk 141 kB; games lazy-loaded per engine.
  • Accessibility: axe-clean, live regions, labeled controls, keyboard-complete games, full reduced-motion story everywhere except U-2.

2 · Redesign plan

Ordered by impact ÷ effort. Each item preserves the site's intent — it's a portfolio that demos game/web engineering, so the 3D constellation, the five games, and the visual loudness stay. What changes is their cost and failure mode.

P0 · Ship now (each item ≲ 50 lines, ~half a day total)

1. Fix the dead contact email A-3

  • Change: create src/data/contact.js exporting CONTACT_EMAIL; update the three hardcoded sites (Contact form, Footer, nav socials).
  • Migration: replace string literals, add a contract test asserting no example.com address ships.
  • Risk: none. Validate: grep for example.com returns nothing; manual mailto send lands in a real inbox.

2. Error boundaries with graceful 3D fallback A-2

  • Change: a small <ErrorBoundary> class + two instances: one around route content (shows the 404-style panel with a reload action), one around <World> and the Playroom (falls back to the static CSS aurora backdrop that already exists).
  • Migration: none — purely additive. Risk: masking errors in dev; log to console in the boundary's dev branch.
  • Validate: fault-injection test — a component that throws renders the fallback, not a white screen; smoke check still passes.

3. Defer three.js out of the entry graph A-1

  • Change: in World.jsx, move the createBackdrop import into the existing useEffect via await import('../three/backdrop.js'). The engine already bootstraps inside the effect and handles engine.ok === false — render the canvas + labels shell first, upgrade when the chunk arrives.
  • Migration: ~10 lines. Fallback state already designed for WebGL-less clients.
  • Risk: brief moment with no backdrop → acceptable (the aurora/vignette CSS layers remain). Validate: build output no longer lists vendor-three as an entry dependency; Playwright trace shows LCP improves; npm run smoke still green.

4. Readiness-gated preloader A-4

  • Change: replace the fixed 1500+700 ms with: wait for document.fonts.ready + one rAF, with a 400 ms minimum display (brand beat) and a 2 s timeout ceiling; skip entirely when sessionStorage shows a previous boot this session. Add inert to the app shell while the veil is up.
  • Risk: slow connections now wait longer than 1.5 s — bounded by the 2 s ceiling; the progress bar is honest because it tracks real readiness. Validate: TTI before/after on a warm cache; smoke covers both boot paths.

P1 · Next sprint

5. ScrollTrigger refresh strategy P-1

  • Change: ScrollTrigger.refresh() on: ProjectGrid filter change (effect on visible), route change, and window.load. One shared useScrollTriggerRefresh(dep) hook keeps it in one place.
  • Risk: refresh loops with the Playroom's pinned horizontal ScrollTrigger — it already sets invalidateOnRefresh: true, so verify after. Validate: scroll-spy active state correct after filtering at several scroll depths.

6. Nav drawer focus trap + restore U-1

  • Change: extract the game overlay's proven trap into src/hooks/useFocusTrap.js; apply to the drawer; restore focus to the hamburger on close.
  • Validate: Tab cycles only within the open drawer; Escape returns focus to the toggle.

7. Scroll coordinator P-2

  • Change: one module-scope rAF-batched scroll bus (src/hooks/useScrollSignal.js); Nav and useActiveSection subscribe instead of each owning a listener.
  • Risk: low; behavior-preserving refactor. Validate: scroll-spy unchanged; frame count during a fast scroll drops in a performance trace.

8. CursorGlow reduced-motion + pause U-2

  • Change: subscribe to the existing useReducedMotion hook and pause the rAF loop when reduced or when document.hidden.
  • Validate: with reduced-motion emulation, no rAF callbacks fire from CursorGlow.

P2 · Hardening

9. Hoist Hero's inner components A-6

  • Change: move StatCard/TerminalWindow3D/CodeLine to module scope. Constraint: test/hero.test.js requires exactly one const TerminalWindow3D and one <TerminalWindow3D /> — hoisting preserves both tokens. Validate: hero tests pass; no remount churn in a React DevTools profiling pass.

10. CSS dedupe & specificity cleanup M-1

  • Change: delete the duplicate .magnetic-btn block and .focus-ring (the global :focus-visible already covers it); move element-level input/textarea base styles behind a comment or remove them where utilities already win.
  • Validate: visual diff of form + buttons before/after (screenshots at 3 breakpoints).

11. Either add the tooling or fix the claims M-2

  • Change: fast path — add ESLint + Prettier configs (an afternoon, kills an entire class of drift). Keep the TypeScript claim honest either by incremental opt-in (allowJs + checkJs on src/, no rewrite) or by rewording the Stack entry. Validate: npm run lint in CI; zero new warnings.

12. Component behavior tests M-3

  • Change: add vitest + @testing-library/react; cover Contact validation flow, Nav drawer trap, and Games overlay focus behavior. Keep the existing source-contract tests for data invariants. Validate: a deliberately broken render fails the suite.

13. Asset diet P-3

  • Change: subset Satoshi to latin via pyftsubset (scripted, like vendor-fonts.mjs); export WebP/AVIF variants with <picture> fallbacks. Validate: transfer size before/after; visual diff of headings (subsetting changes nothing visible for English copy).

P3 · Optional

  • Engine harness A-5: extract a ~80-line shared harness (fixed-timestep loop, resize observer, input binding, dispose) into src/three/engine.js; migrate the playroom first, games opportunistically. Do not rewrite the games — they're the portfolio's proof of work.
  • Runtime error observability A-2+: the boundary from P0.2 can ship errors to any endpoint later via a report-to CSP directive; document as accepted risk until then (no backend = no collector).
  • Soft-404 honesty U-3: unsolvable on GitHub Pages without edge rules; accepted.
